## 2. 逐项拆解

### 2.1 FFmpeg

**库分工**（每库一个 `.so/.dll`，按需链接）

| 库 | 职责 | 嵌进工作站时谁在用 |
|---|---|---|
| `libavformat` | 容器封装/解封装、`AVFormatContext`、seek 入口 | 所有素材探测、mux/demux |
| `libavcodec` | 编解码器实现、`AVCodecContext`、硬件加速封装 | 解码预览帧、编码导出 |
| `libavutil` | 公共结构体、`AVFrame`、`AVRational` 时间基、`AVBuffer` | 全局 |
| `libavfilter` | 滤镜图，`AVFilterGraph` → `avfilter_graph_parse2()` | 调色、缩放、叠加、字幕烧入 |
| `libswscale` | 像素格式/尺寸转换 | CPU 侧色彩与缩放 |
| `libswresample` | 音频重采样/声道布局 | 采样率对齐 |
| `libavdevice` | 采集设备输入 | 摄像头/采集卡 |

来源：https://github.com/FFmpeg/FFmpeg 【开源代码】

**授权边界**：官方明文 "FFmpeg is licensed under the GNU Lesser General Public License (LGPL) version 2.1 or later. However, FFmpeg incorporates several optional parts and optimizations that are covered by the GNU General Public License (GPL) version 2 or later. If those parts get used the GPL applies to all of FFmpeg." 且 "FFmpeg is not available under any other licensing terms, especially not proprietary/commercial ones, not even in exchange for payment." 官方给的 LGPL 落地清单：不带 `--enable-gpl`、不带 `--enable-nonfree`、Windows 上动态链 DLL、随包分发对应源码、发布 `git diff`、标注 configure 行。来源：https://www.ffmpeg.org/legal.html 【官方文档】

**硬件编码**（Windows 列实测可用性）

| API | Windows AMD | Windows Intel | Windows NVIDIA | 编码器名 | 解码器名 |
|---|---|---|---|---|---|
| AMF | Y | N | N | `h264_amf` / `hevc_amf` / `av1_amf` | 走 D3D11VA |
| NVENC / NVDEC / CUVID | N | N | Y | `h264_nvenc` / `hevc_nvenc` | `-hwaccel cuda` / `h264_cuvid` |
| Direct3D 11 | Y | Y | Y | — | `-hwaccel d3d11va` |
| DXVA2 (D3D9) | Y | Y | Y | — | `-hwaccel dxva2` |
| libmfx（Intel Quick Sync） | N | Y | N | `*_qsv` | 内部 hwaccel |
| Vulkan | Y | Y | Y | N | `-hwaccel vulkan` |
| Media Foundation | Y | Y | Y | N（"Possible but not implemented"） | N |

要点：硬件编码器画质普遍低于 x264/x265 同码率；硬件帧在显存里，和软件滤镜之间要靠 `hwupload` / `hwdownload` 搬运；`-hwaccels` 可列出本机可用项。来源：https://trac.ffmpeg.org/wiki/HWAccelIntro 【官方文档】

**Filter graph**：`avfilter_graph_create_filter()` + `avfilter_graph_parse2()` 组图，`AV_BUFFERSRC` / `AV_BUFFERSINK` 作为进出端；支持多输入多输出与 `filter_complex` 同级语义。GPU 侧有 `scale_cuda`、`scale_npp`、Vulkan video filters、OpenCL filters。来源同上 【官方文档】

**精确帧级 seek**

| 写法 | 行为 | 精度 | 速度 |
|---|---|---|---|
| `-ss` 在 `-i` 之前 | 按关键帧定位 | 从 FFmpeg 2.1 起，转码场景下即为帧准（可用 `-noaccurate_seek` 退回旧行为） | 极快 |
| `-ss` 在 `-i` 之后 | 逐帧解码丢弃到目标位 | 帧准 | 慢，偏移越大越慢 |
| `-ss` 配合 `-c copy` | 只在 I 帧切分 | 非帧准，起点会带无画面的音频段 | 最快 |

结论：做时间线精确抽帧用「`-ss` 前置 + 转码（或 `-ss` 后置解码）」，做无损粗切接受 I 帧边界。来源：https://trac.ffmpeg.org/wiki/Seeking 【官方文档】

### 2.2 MLT Framework

- README 首句："MLT is a LGPL multimedia framework designed for video editing." 来源：https://raw.githubusercontent.com/mltframework/mlt/master/README.md 【开源代码】
- **插件架构**：文档站把插件叫 Services，分五类——Producers（输入源）、Filters、Transitions（混音/合成）、Consumers（输出/播放）、Links（时间特效）。另有 `MLT++` C++ 包装库、Doxygen API、脚本语言绑定、Headless Rendering 专章。来源：https://www.mltframework.org/docs/ 【官方文档】
- **XML 工程格式**：MLT XML 是 API 内部结构的直映射，"A MLT XML document is essentially a list of 'producers'"；三类 producer——Basic Producers / Playlists / Multitracks；DTD 在 `mlt/src/modules/xml/mlt-xml.dtd`，**解析器为非验证型（non-validating）**。手写 XML 的推荐组织法：先为每个唯一素材建 producer，再为每条轨建 playlist，再建 multitrack 挂滤镜与转场，最后加全局滤镜。来源：https://www.mltframework.org/docs/mltxml/ 【官方文档】
- **独立库嵌入**：LGPL-2.1 + 纯 C ABI + 独立 XML 层，可作为一个 `libmlt` 直接塞进 Qt/Rust/Electron 后端；Kdenlive 与 Shotcut 都是这么用的（两者上层各自实现，引擎共用 MLT）。来源：https://github.com/mltframework/mlt 【开源代码】
- **硬限制**：XML 解析非验证 → 工程文件校验得自己写；GPU 处理走 OpenGL 模块，跨显卡驱动行为要自测；`melt` 命令行与库 API 是两套调用面，预览与导出的帧一致性要单独对齐。来源：https://www.mltframework.org/docs/ 【官方文档】

### 2.3 OpenTimelineIO

**数据模型**（官方 serialized schema，字段级）

| 类 | 关键字段 | 语义 |
|---|---|---|
| `Timeline` | `tracks`, `global_start_time`, `metadata` | 顶层容器 |
| `Stack` | `effects`, `markers`, `source_range` | 轨道堆叠容器 |
| `Track` | `kind`（Video/Audio）, `children` | 一条轨，子项有序 |

| `LinearTimeWarp` | `time_scalar`（2.0=倍速，0.5=半速） | 线性变速；不改父项时长，改媒体播放速度 |
| `FreezeFrame` | 继承 `LinearTimeWarp` | 定格首帧 |
| `Marker` | `marked_range`, `color`, `comment` | 标记，坐标系为所属 Item |
| `ExternalReference` | `target_url`, `available_range` | 外部媒体引用 |

| `GeneratorReference` | `generator_kind`, `parameters` | 生成器（色板/噪声） |
| `MissingReference` | — | 媒体缺失占位 |
| `SerializableCollection` | `children` | 素材箱语义，可装多条 Timeline |

时间基：`RationalTime(rate, value)`、`TimeRange(start_time, duration)`、`TimeTransform(offset, rate, scale)`。来源：https://opentimelineio.readthedocs.io/en/latest/tutorials/otio-serialized-schema.html 【官方文档】

**适配器机制**：适配器不是类继承，而是一个 Python 模块实现 `read_from_file` / `read_from_string` / `write_to_file` / `write_to_string` 中至少一个，再加一个 JSON 声明其能力（suffixes 等）。另有 SchemaDef 插件、MediaLinker 插件、HookScript 钩子、`PluginManifest` 做插件索引。来源：同上 【官方文档】

**做自有格式转换中枢的判定**：成立。自研工程格式 → 写一个 SchemaDef 插件把私有字段塞进 `metadata`，再写一对适配器对接 EDL/XML/AAF/FCPXML；`Timeline.range_of_all_children` 与 `RationalTime` 保证帧/秒换算不出漂移。来源：同上 + https://github.com/AcademySoftwareFoundation/OpenTimelineIO 【推断】

**硬限制**：版本 tag 停在 `v0.18.1`，API 未到 1.0，`0.x` 之间仍有字段变动（文档站已跑到 0.19.0.dev1）；C++ 侧功能面窄于 Python 侧，繁重逻辑要放 Python 进程。来源：https://github.com/AcademySoftwareFoundation/OpenTimelineIO 【开源代码】

### 2.4 GStreamer

- **pipeline 与 NLE**：GES 建立在 GStreamer + GNonLin 之上；核心对象 `GESTimeline` 本身是 `GstElement`，可直接挂进任何 pipeline；`GESLayer`（用户视角排布）/ `GESTrack`（输出流）双概念；`GESPipeline` 是时间线专用便利管线。`nlecomposition` / `nleoperation` / `nlesource` / `nleurisource` 四个元素构成 nle 底层。来源：https://gstreamer.freedesktop.org/documentation/gst-editing-services/index.html 、https://gstreamer.freedesktop.org/documentation/nle/index.html 【官方文档】
- **授权**：GES 明文 "released under the GNU Library General Public License (GNU LGPL)"。来源同上 【官方文档】
- **Windows 部署复杂度**：
  - 官方支持到 Windows 11+，推荐 VS2019+。
  - 装机要装两套 MSI：`gstreamer-1.0-msvc-x86_64-{VERSION}.msi`（runtime）与 `gstreamer-1.0-devel-msvc-x86_64-{VERSION}.msi`（开发文件），另有 Merge Modules 供 installer 打包。
  - 运行时靠 `%GSTREAMER_ROOT_X86_64%\bin` 进 PATH，或 `GST_PLUGIN_PATH` / `GST_PLUGIN_SYSTEM_PATH` 指路；插件默认在 `<dll 所在目录>\..\lib\gstreamer-1.0`。
  - 官方文档自陈："NOTE: these instructions are out of date, exercise caution while following them"（VS2010 时代的教程段）。
  - 装之前要关 Visual Studio，否则环境变量读不到。
  - 来源：https://gstreamer.freedesktop.org/documentation/installing/on-windows.html 【官方文档】

### 2.5 OpenFX

- **标准定位**：插件（shared library）与宿主（host）之间的 C ABI 契约，2004 年起，现属 Academy Software Foundation。来源：https://openeffects.org/ 【官方文档】

- **1.4 → 1.5 的实际差异**（官方 release notes 原文归纳）：
  - GPU Rendering Suite 增加 **Metal / CUDA / OpenCL** 支持（Images 与 Buffers 两类），含 half-float 位深。
  - 新增 **`OfxDrawSuiteV1`** —— 不依赖 OpenGL 就能画 overlay。
  - 新增 **`OfxSetHost()`** action（宿主最先调用）。
  - 新增字符串枚举参数 **`kOfxParamTypeStrChoice`** 与排序属性 **`kOfxParamPropChoiceOrder`**（新版插件可重排菜单项而保持向后兼容）。

### 2.7 Blender

Apart from the GNU GPL, Blender is not available under other licenses."。含义：进程内链接 Blender 代码 → 你的程序整体要吃 GPL；**子进程 + 命令行 + 文件交换** 这条边界是站得住的通行做法（Blender 自身分发的 `bpy` 轮子也按 GPL 走）。来源：https://raw.githubusercontent.com/blender/blender/main/COPYING 【开源代码】

### 自建统一模型网关的接口设计要点

MAGPIE 已经把「本机网关 + 协议双向翻译 + 路由组 + 账号级额度顺位」这套跑通了，要自建就照这几处下手：

| 层 | 要点 | 落地做法 |
|---|---|---|
| **OpenAI 兼容层** | `POST /v1/chat/completions`、`POST /v1/responses`、`GET /v1/models`；`model` 字段既认真实模型名也认别名 | 别名表 + `model_alias → {provider, upstream_model, params_override}` |
| **SSE 流式** | `Content-Type: text/event-stream`，逐条 `data: {...}\n\n`，末尾 `data: [DONE]`；`stream_options.include_usage=true` 拿末帧 usage | 全链路过 SSE，不做整包缓冲；客户端断连要往下游发取消 |
| **协议互转** | Anthropic Messages ↔ OpenAI Chat ↔ Responses ↔ Gemini 四向翻译 | 抽象一层内部 IR（messages/tool_calls/usage），进出各写一个 codec |
| **function calling** | 三家的工具声明结构不同：OpenAI `tools[].function.parameters`（JSON Schema）、Anthropic `tools[].input_schema`、Gemini `functionDeclarations` | 内部统一成 `{name, description, parameters(JSON Schema)}`，出口再投影 |
| **多供应商故障切换** | 按错误分类决策：429/5xx/超时 → 顺位重试；400/401 → 直接上抛不重试 | 路由组数组 + 每供应商独立熔断计数 + 指数退避上限 |
| **token 计量** | 请求侧估算（tiktoken 系）＋ 响应侧读 usage；按 provider/account/model/day 四维落库 | 中间件记 `{ts, agent, provider, model, prompt_tokens, completion_tokens, cached_tokens, latency_ms, status}` |
| **额度控制** | 账号级 quota（订阅制按窗口重置）＋ 全局预算；耗尽即摘出路由组 | 每账号带 `remaining / window_reset_at`，路由选择时先过滤 |
| **流中切换** | 已经吐出首 token 后不换供应商（会串味），只在首包前切换 | 加「首包超时」阈值，超时就换路 |
| **脱敏与审计** | 出站前对密钥/PII 做掩码，入站全量落审计日志 | 与 MAGPIE 的 "Masking" 同位 |

来源：MAGPIE 官方 README / reference.md 与站点流程图 https://usemagpie.ai 【官方文档】；OpenAI 兼容与 SSE 语义属通行接口约定 【推断】

### 把桌面软件包成 MCP Server 的通行做法

| 环节 | 规范要求 / 通行姿势 |
|---|---|
| **工具命名** | 长度 1–128 字符（含端点）、区分大小写；允许字符仅 `A-Z a-z 0-9 _ - .`；不含空格与逗号；服务端内唯一。示例：`getUser`、`DATA_EXPORT_v2`、`admin.tools.list`。跨服务聚合时客户端/代理要自己做去重（如按服务名前缀），且服务端 `serverInfo.name` 不保证唯一，它当不了去重键。来源：https://modelcontextprotocol.io/specification/2026-07-28/server/tools.md 【官方文档】 |
| **工具粒度** | 视频工作站里按「动作」切，不按「内部 API」切：`timeline.add_clip`、`timeline.split_at_frame`、`render.enqueue`、`media.probe`、`transcript.search`。单工具参数控制在 15 个以内，复杂结构走 `$ref` 式 schema |
| **命名约定（本工程）** | 前缀取子系统：`timeline.*` / `render.*` / `media.*` / `ai.*` / `project.*`，后缀用动词。来源：上条规范 + 本工程约定 【推断】 |
| **长任务进度通知** | 客户端给 `progressToken`；服务端按帧或按百分比发 `notifications/progress`。渲染这类任务：`progress` 用已渲帧数，`total` 用总帧数，`message` 放 "frame 240/1200 · 12.4 fps"。`progress` 必须单调递增，浮点可用。来源：progress.md 【官方文档】 |
| **elicitation（追问）** | 当工具缺参数（如"用哪个 LUT"）时，服务端发起 elicitation 让宿主弹 UI 收集，而不是让工具调用失败。桌面侧正好把 elicitation 映射到原生弹窗。来源：https://modelcontextprotocol.io/specification/2026-07-28/client/elicitation 【官方文档】 |
| **sampling** | 让宿主（客户端）代为调 LLM，服务端不自带 key。视频工作站里做"选段打分"这类小判断时，用 sampling 比内置 API key 更干净。来源：client/sampling 【官方文档】 |
| **resources** | 把工程、时间线、素材清单暴露成 `video://project/{id}/timeline` 这类 URI，模型可读不可改。来源：server/resources 【官方文档】 |
| **prompts** | 把"自动粗剪""按字幕对齐""生成 30 秒预告"做成 prompt 模板，用户在前端选。来源：server/prompts 【官方文档】 |
| **传输选择** | 纯本机：stdio（客户端拉起你的 exe，零端口零鉴权）。要跨进程/跨机/多客户端共享：Streamable HTTP + OAuth。来源：transports 【官方文档】 |
| **HTTP 头联动** | 2026-07-28 起有 `x-mcp-header` 扩展属性，可把指定工具参数镜像进 HTTP 头（Streamable HTTP 下用） | server/tools.md 【官方文档】 |
| **服务发现** | 2026-07-28 新增独立 Discovery 页 | https://modelcontextprotocol.io/specification/2026-07-28/server/discover.md 【官方文档】 |

## 5. 候选底座组合

**方案甲：Qt + MLT + FFmpeg + OTIO（全 C++ 单体，Windows 优先）**

| 层 | 选型 | 授权姿态 |
|---|---|---|
| 壳 | Qt 6（LGPLv3 模块集，动态链 DLL） | 闭源可站住；碰 GPL-only 模块就转商业 |
| 时间线引擎 | MLT 7.42（LGPL-2.1） | 动态链接 |
| 编解码 | FFmpeg 9.1（不带 `--enable-gpl`） | 动态链 DLL + 分发源码 |
| 工程格式 | OTIO 0.18（Apache-2.0） | 无约束 |
| 调色 | OCIO 2.6（BSD-3） | 无约束 |
| 特效 | 自实现 OFX host（BSD-3 头文件） | 无约束 |
| AI | 独立 Python 进程（whisper.cpp / faster-whisper）+ gRPC | 进程边界隔离 |

代价：Qt 的 LGPL 模块裁剪要提前规划；MLT 的 XML 解析非验证，工程文件校验自己写。来源：合计前述各页 【推断】

**方案乙：Tauri + 独立 C++ 引擎进程（Electron 系留作备选）**

Tauri（Apache-2.0）当壳，C++ 引擎跑成独立进程，gRPC over localhost 通信；Rust 侧负责进程生命周期、文件监视、模型网关代理（可直接抄 MAGPIE 的 127.0.0.1 思路）。前端用 React 做时间线 UI，状态以 OTIO JSON 为唯一真相。代价：WebView2 版本随系统走，UI 一致性与 GPU 渲染路径要自测。来源：https://github.com/tauri-apps/tauri 【推断】

**方案丙：Electron + FFmpeg 命令行 + OTIO（最快出原型）**

Electron 45 + Node 侧调 FFmpeg 可执行文件，LosslessCut 的路子；先不做 in-process 引擎，全部走子进程 + 文件。代价：内存与安装包体积高，帧级预览延迟大。适合先验证 AI 侧，再换引擎。来源：https://github.com/electron/electron + https://github.com/mifi/lossless-cut 【推断】
