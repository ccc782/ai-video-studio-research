### 1.3 官方 README 原文（PyPI 包内转抄，逐字）

- `ProjectManager.CreateProject`：Return Type: Project；Comment: Creates and returns a project if projectName (string) is unique, and None if it is not.
- `MediaPool.ImportMedia`：Return Type: [MediaPoolItems]；Comment: Imports specified file/folder paths into current Media Pool folder. Input is an array of file/folder paths. Returns a list of the MediaPoolItems created.
- `MediaPool.AppendToTimeline`：以 MediaPoolItem 列表或 clipInfo map 追加到时间线末位。
- `Timeline.SetCurrentTimecode`：Sets current playhead position from input timecode for Cut, Edit, Color, Fairlight and Deliver pages.
- `TimelineItem.AddFusionComp`：Return Type: fusionComp；Comment: Adds a new Fusion composition associated with the timeline item.
- `TimelineItem.SetLUT`：Sets LUT on the node mapping the node index provided, 1 <= nodeIndex <= total number of nodes. The operation is successful for valid lut paths that Resolve has already discovered (see Project.RefreshLUTList).
- `TimelineItem.SetCDL`：map 键为 "NodeIndex"、"Slope"、"Offset"、"Power"、"Saturation"。
- `Project.StartRendering`：Starts rendering jobs indicated by the input job ids.
- `Project.GetRenderCodecs`：Returns a dict (codec description -> codec name) of available codecs for given render format.
- `Timeline.Export`：Exports timeline to 'fileName' as per input exportType & exportSubtype format.
- `GalleryStillAlbum.ExportStills`：格式限定 dpx、cin、tif、jpg、png、ppm、bmp、xpm。
来源：https://pypi.org/project/davinci-resolve-api/ [官方文档]（官方 README 文本经第三方包转抄，措辞与 README 一致）

### 1.4 削切类原语不存在

对 Timeline 做帧级剃刀切分、把 TimelineItem 移到别的起始帧、ripple delete / overwrite / rolling edit，这套对象模型里没有对应方法。第三方在 Resolve 19.1.4 上 grep 应用包与 README 后得同一结论，并在 CLI 里改用打标记的占位实现。
来源：https://pypi.org/project/davinci-resolve-cli/ [第三方研究]

### 2.2 初始化四步

1. 把 `<RESOLVE_SCRIPT_API>/Modules` 塞进 `sys.path`；
2. `import DaVinciResolveScript`（模块文件 `<API>/Modules/DaVinciResolveScript.py`）；
3. 内层靠 `fusionscript.{dll,so}` 做原生绑定，PyPI 的 da Vinci 封装直接 `imp.load_dynamic('fusionscript', library)` 再 `_bmd.scriptapp('Resolve')`；
4. `resolve = DaVinciResolveScript.scriptapp("Resolve")`，返回 None 表示实例没起。
来源：https://pypi.org/project/davinci-resolve-cli/ ；https://pypi.org/project/davinci-resolve-api/ [开源代码]
`DaVinciResolveScript.py` 本体只做动态装载管道，真正的 API 表面由原生库在运行时绑定。来源：https://pypi.org/project/davinci-resolve-cli/ [第三方研究]

### 2.3 外部脚本开关（Studio 限定）

Preferences → System → General → External Scripting Using：None / Local / Network。None 时只有 Console 窗口里的脚本能跑；Local 放行同机外部脚本与应用；Network 放行网络侧连接。
来源：官方手册第 109 页 https://documents.blackmagicdesign.com/UserManuals/DaVinci_Resolve_21_Reference_Manual.pdf [官方文档]
第三方同口径描述：Preferences → System → General → External scripting 设为 Local，默认是 None。来源：https://pypi.org/project/davinci-resolve-cli/ [第三方研究]

### 2.4 Python 2 / Python 3 / Lua

- FusionScript 是 Fusion 侧脚本环境的统称，含 Lua、Python 2 与 Python 3，各自只在部分上下文可用。来源：手册第 1640 页 [官方文档]
- Fusion Settings → Script 面板给出 Python Version 两项二选一（对应 Py2 / Py3 解释器）。来源：手册第 1668 页 [官方文档]
- Lua 与 Python 脚本目录由 Path Map 的 `Scripts` 项指定，`LuaModules` 单独指 Lua 模块目录；Fuses、Macros、Edit templates、FusionTemplates 各有独立 Path Map。来源：手册第 1664、1665 页 [官方文档]
- 页内交互脚本走 Workspace → Console（Resolve）/ View → Console（Fusion Studio），可直接读 FusionScript 输出、直接敲 FusionScript。来源：手册第 1550、1641 页 [官方文档]
- `fuscript` 在 21 手册全文没有出现（0 次命中）。其存在与用法本轮没有公开可引证据。 [未证实]
- 无 UI 连接：`Resolve.exe -rr` 起 Remote Rendering 守护，静默等远程渲染任务；macOS 为 `./Resolve -rr`，Linux 为 `/opt/resolve/bin/resolve -rr`。来源：手册第 4217 页 [官方文档]

## 3. 工程存储

### 3.1 库 / 库类型

Project Library（旧称 project database）是存一个或多个工程的数据库，只存"怎么用媒体"的指令，不存原始媒体；同一时刻只连一个库。三类：Local、Network、Cloud。来源：手册第 4309 页 [官方文档]
Local 库默认落在名为 **Resolve Disk Database** 的文件夹，连接既有库时该目录惯用名是 **Resolve Disk Project library**。来源：手册第 4310、4311 页 [官方文档]

### 3.2 Disk 与 PostgreSQL 两套后端

API 层面直接暴露后端类型：`ProjectManager.SetCurrentDatabase` 的 `'DbType'` 取 `'Disk'` 或 `'PostgreSQL'`，`'DbName'` 是库名，`'IpAddress'` 是 PostgreSQL 服务器地址（缺省 127.0.0.1）。来源：https://pypi.org/project/davinci-resolve-api/ [官方文档]
网络库（Network Project Library）跑在 DaVinci Resolve Project Server 上，底层是 PostgreSQL：默认账号 `postgres` / 口令 `DaVinci`，可加成员与角色。来源：手册第 4315、4323、4325 页 [官方文档]
"Optimize" 动作的措辞是 vacuum 掉空余空间并重建索引，这是关系库的常规维护动作。来源：手册第 4317 页 [官方文档]
Disk 库的具体文件格式（是否 SQLite 单文件、文件命名）官方手册与 README 都没有写。按 DbType 命名与 vacuum 语义推定为 SQLite 系文件库。 [推断]

### 3.3 表结构（Sm2Projects / Sm2Timeline / Sm2Sequence）

本轮抓取的官方 PDF（4444 页全文）与官方 README 转抄文本里，`Sm2Projects`、`Sm2Timeline`、`Sm2Sequence`、`ResolveDiskDatabase` 全部 0 命中。公网也没有采到列出这批表名的可引来源（GitHub 侧网络不通）。因此"表名清单"与"能否直接读库"这两条不给结论。 [未证实]
给自动化落地时的替代路径：走 `ProjectManager.ExportProject` / `RestoreProject` 与 `ArchiveProject`，不碰库文件。来源：https://pypi.org/project/davinci-resolve-api/ [官方文档]

### 3.4 四类工程的磁盘产物

| 后缀 | 是什么 | 含什么 |
|---|---|---|
| `.drp` | DaVinci Resolve Project File，单工程导出/导入 | 工程全量；`ExportProject` 的 `withStillsAndLUTs` 默认 True，把静帧与 LUT 一起打包 |

## 4. 导出 / 交换格式

### 4.1 OTIO 双向

`.otio` 只含时间线元数据，体积极小，导入方自行链媒体；`.otioz` 把时间线元数据与全部媒体 zip 成单包，导入时媒体自解压到 `.otioz` 同目录并自动链接。导出路径 File > Export > Timeline，格式选 .otio 或 .otioz。
来源：手册第 544、547、4242 页 [官方文档]
`.otio` 本体是 JSON：顶层对象带 `"OTIO_SCHEMA": "Timeline.1"` 这类类型+版本键，嵌套 Stack → Track → Clip/Transition，时间用 `RationalTime`（rate + value）。来源：https://opentimelineio.readthedocs.io/en/latest/tutorials/otio-file-format-specification.html [官方文档]
官方手册结论：Resolve 之间传时间线用 `.drt` 最稳；跨应用传优先 `.otio` / `.otioz`，不支持时退回 XML 或 AAF。来源：手册第 4242 页 [官方文档]

### 4.2 XML / AAF / EDL / ADL

- FCP 7 XML 与 FCP X XML 都能导入；Premiere 侧建议 5.5.1 以上导出。来源：手册第 521、522 页 [官方文档]
- AAF 有完整导入对话框（Import timeline、Use sizing information、Import log messages as markers、Import AAF to current timeline、Insert Additional Tracks、Insert With Offset、Mixed frame rate format）。来源：手册第 527、528、529 页 [官方文档]
- ADL（AES31 Audio Decision List）只进不出，Resolve 不导出 ADL。来源：手册第 548 页 [官方文档]
- 导出侧还有 CDL、ALE、Edit Index 的 CSV/TXT、Media Pool Metadata 的 CSV（`MediaPool.ExportMetadata`）。来源：手册第 4246、4247、4250 页 [官方文档]
- `Timeline.ImportIntoTimeline` 的 importOptions 支持 autoImportSourceClipsIntoMediaPool、ignoreFileExtensionsWhenMatching、linkToSourceCameraFiles、useSizingInfo、importMultiChannelAudioTracksAsLinkedGroups、insertAdditionalTracks、insertWithOffset、sourceClipsPath、sourceClipsFolders。来源：https://pypi.org/project/davinci-resolve-api/ [官方文档]

### 4.3 DCP / IMF

原生 DCP 与 IMF 编解码为 Studio 版能力，手册单开一章：原生非加密 DCP 编解码、原生 IMF 编解码、DCP Reels 分段、Supplemental Packages、Dolby Vision 元数据、Photon 校验；加密 DCP 与 KDM 走 Fraunhofer easyDCP 授权。来源：手册第 4218 页目录 [官方文档]

### 4.4 渲染预设机制

- 自定义预设是 **.xml 文件**，Deliver 页 Render Settings 三点菜单里 Export Preset / Import Preset；新预设会出现在时间线右键的 "Add to Render Queue Using" 菜单。来源：手册第 4194、4195 页 [官方文档]
- 脚本侧一一对应：`GetPresetList`、`GetRenderPresetList`、`GetRenderFormats`、`GetRenderCodecs`、`SetCurrentRenderFormatAndCodec`、`GetRenderResolutions`、`LoadRenderPreset`、`SaveAsNewRenderPreset`、`SetRenderSettings`、`AddRenderJob`、`StartRendering`、`GetRenderJobStatus`、`DeleteRenderJob`、`DeleteAllRenderJobs`、`IsRenderingInProgress`、`StopRendering`、`GetCurrentRenderMode`、`SetCurrentRenderMode`。来源：https://pypi.org/project/davinci-resolve-types/ [开源代码]
- 批量渲染的两条路：脚本对多个时间线逐个 `AddRenderJob` 再 `StartRendering(jobIds)`；UI 侧跨工程批渲染用 Render Queue 的 Show All Projects，把当前用户在各工程排好的任务一起放出来。来源：手册第 4214 页 [官方文档]
- ProRes / DNxHR 的落点是 Deliver 页 Format + Codec 两个下拉，`GetRenderCodecs` 按 Format 返回「编码器描述 → 编码器名」字典；具体编码器名随版本增减，手册明说格式列表每版都会变。来源：手册第 4196 页；docstring `GetRenderCodecs` [官方文档]

## 5. Fusion 页

### 5.1 节点图与 comp 文件

- Fusion comp 文件是**可读纯文本**，任何文本编辑器能开能改；用 Word 之类会写入富文本格式，Fusion 就读不动了。来源：手册第 1389 页 [官方文档]
- 自动备份文件后缀是 `.autosave`，同名放同目录。来源：手册第 1389 页 [官方文档]
- Resolve 里 File > Export Fusion Composition 导出的 `.comp` 只含节点树：没进 Node Editor 的 clip 不进 Fusion Studio 的 bin，ResolveFX 不随迁；MediaIn 自动转 Loader，MediaOut 自动转 Saver，路径一致即自动重链。反向 File > Import Fusion Composition 会把整棵树替换掉。来源：手册第 1390 页 [官方文档]
- ".comp 是 Lua 表文本"这一说法，官方手册只说到"可读纯文本"，没写序列化语言。 [未证实]

### 5.2 Fusion 脚本 API

- `Resolve.Fusion()` 返回 Fusion 对象，是 Fusion 脚本的起点（docstring：Returns the Fusion object. Starting point for Fusion scripts.）；原生层也可 `scriptapp('Fusion')`。来源：https://pypi.org/project/davinci-resolve-api/ [官方文档]
- 从 Resolve 侧挂 comp 走 `TimelineItem.AddFusionComp` / `ImportFusionComp` / `ExportFusionComp` / `GetFusionCompByName` / `GetFusionCompNameList` / `GetFusionCompCount` / `DeleteFusionCompByName` / `LoadFusionCompByName` / `RenameFusionCompByName`；时间线级还有 `InsertFusionCompositionIntoTimeline`、`InsertFusionGeneratorIntoTimeline`、`InsertFusionTitleIntoTimeline`。来源：https://www.npmjs.com/package/davinci-resolve-types [开源代码]
- `fusion.GetCurrentComp()` 这类 comp 内方法属于 Fusion 脚本文档（Help > Documentation > Fusion Scripting Documentation），Resolve 手册指过去但不复述。来源：手册第 1641 页 [官方文档]
- FusionScript 的脚本分档：Utility Scripts（File > Scripts）、Comp Scripts（Script 菜单或 Console）、Tool Scripts（工具右键 Scripts），另有 Startup Scripts、Scriptlibs、Bin Scripts、Event Suites、Hotkey Scripts、Intool Scripts、SimpleExpressions；Fuses 与 ViewShaders 也架在 FusionScript 上。来源：手册第 1640、1641 页 [官方文档]

### 5.3 表达式

- SimpleExpression 的进入方式是在数值框输等号回车；内容是**一行 Lua** 加 Fusion 特化简写。`time` 返回当前帧；`Merge1.Blend` 读另一节点某输入值；`Merge1:GetValue("Blend", time-5)` 读另一帧的值；条件式用 `iif(cond, a, b)`。来源：手册第 1634、1640 页 [官方文档]
- Expression 修饰器是 SimpleExpression 的加强版，参数更多、空间更大；另有 Calculation、Publish、Connect To 做单向/双向参数联动。来源：手册第 1633 页 [官方文档]

### 5.4 Fuse 与 DCTL

- Fuse 是用 **Lua** 写的 Fusion 原生插件，运行时即时编译，不需要 C++ 工具链；比等价 OFX 慢，但能吃到 Fusion 现有节点与 GPU 加速。文件后缀 `.fuse`。安装目录：macOS `~/Library/Application Support/Blackmagic Design/DaVinci Resolve/Fusion/Fuses`；Windows `%APPDATA%\Blackmagic Design\DaVinci Resolve\Support\Fusion\Fuses`；Linux `~/.local/share/DaVinciResolve/Fusion/Fuses`。来源：手册第 1872 页 [官方文档]
- DCTL（DaVinci Color Transform Language）是 C 风格的颜色变换脚本，被 Resolve 当 LUT 用；与 1D/3D LUT 的区别是直接跑数学函数而不是查表插值，且**在 GPU 上原生跑**。文件名以 `.dctl` 结尾，放 LUT 目录：Windows `C:\ProgramData\Blackmagic Design\DaVinci Resolve\Support\LUT`，macOS `~/Library/Application Support/Blackmagic Design/DaVinci Resolve/LUT/`，Linux `/home/resolve/LUT`。启动后出现在 Color 页节点右键 DaVinci CTL 子菜单。来源：手册第 4422 页 [官方文档]
- DCTL 语法要点（原文可照抄）：每个函数前加 `__DEVICE__`；主入口固定为 `__DEVICE__ float3 transform(float p_R, float p_G, float p_B)`，返回值必须是 float3；带空间访问时入参换成 `int p_Width, int p_Height, int p_X, int p_Y, __TEXTURE__ p_TexR, __TEXTURE__ p_TexG, __TEXTURE__ p_TexB`，取样用 `_tex2D(p_TexR, x, y)`；常量内存用 `__CONSTANT__`，传参用 `__CONSTANTREF__`；向量类型 float2/float3/float4，构造用 `make_floatN()`；浮点字面量必须带 `f`。内建函数名带下划线前缀：`_fabs`、`_powf`、`_logf`、`_log2f`、`_log10f`、`_exp2f`、`_expf`、`_copysignf`、`_fmaxf`、`_fminf`、`_saturatef`、`_sqrtf`、`_ceil`、`_floor`、`_fmod`、`_fremainder`、`_round`、`_hypotf`、`_atan2f`、`_sinf`、`_cosf`、`_acosf`、`_asinf`、`_fdivide`、`_frecip`；整数型支持 min/max/abs/rotate；另开放 acosh、acospi、asinh、asinpi、atan、atanh、atanpi、atan2pi、cbrt、cosh、cospi、exp10、expm1、trunc、fdim、fma、lgamma、log1p、logb、rint、round、rsqrt、sincos、sinh、sinpi、tan、tanh、tanpi、tgamma。来源：手册第 4422–4425 页 [官方文档]

### 5.5 OFX

Fusion 页与 Fusion Studio 都支持第三方 Open FX；Resolve FX 在 Fusion 页的 Effects Library 里与 OFX 同列，Fusion Studio 没有 Resolve FX。另有一个反向玩法：DaVinci Resolve Renderer OFX 把 Resolve Studio 整个变成一个大 OFX 插件，读 `.DRX` 静帧还原调色（原生 color/sizing 面板、多数 Resolve FX、多数第三方 OFX 可迁；时域类 FX 与 Magic Mask 不迁）。
来源：手册第 1869、1870、4411、4412 页 [官方文档]

## 7. 音频（Fairlight）

- 引擎侧两条总线体系：默认 FlexBus，单个 clip 与 track 上的插件数量不设上限；切到 Fixed Bus Legacy 时上限 480 个。插件从每条轨的控制条或 Inspector 进（clip 与 track 两处）。来源：手册第 4081 页 [官方文档]
- Fairlight FX 是 Resolve 自带的专有插件，macOS / Windows / Linux 三平台原生跑；Channel Dynamics、EQ、Multiband Compressor、Limiter、Reverb、Ambisonics Meter 为 Ambisonics 原生、支持多声道。来源：手册第 4081 页 [官方文档]
- Track FX 固定几只：Voice Isolation、Dialogue Leveler、Dialogue Separator、Music Remixer、Ducker；其中 Voice Isolation 是 DaVinci Neural Engine 的 AI 效果，Studio 限定。来源：手册第 3837 页 [官方文档]
- VST：**支持 VST3**；VST 效果在 macOS 与 Windows 可用，Linux 不可用；AU 只有 macOS。等宽声道映射规则：立体声 VST 插到 LCR / LCRS / 5.1 Link Group 上时左右声道自动分配到 Link Group 的左右声道。来源：手册第 4082 页 [官方文档]
- 总线结构与路由：Bus Format 建 mono 到多声道 Atmos 总线，Bus Assign 做 bus→track、track→bus、bus→bus 的 patch；通道条有 Bus Sends（需至少两条总线）、Bus Outputs、VCA 1–10（池子共 128 个）。来源：手册第 3838、3839、4441 页 [官方文档]
- 混音器分两组通道条：左边每轨一条，右边每条总线一条。来源：手册第 3836 页 [官方文档]
- 导出规则里的一条硬约束：Deliver 页导 Pro Tools 时，音频效果既不导出也不烘焙，FairlightFX、EQ、Compression、Pitch、Elastic Wave 全部被忽略；但轨道与片段的音量自动化连同关键帧全导，iXML 元数据（含声道名）照导，同步文件导出的音频按同步源文件的时间码与命名走。来源：手册第 4079、4080 页 [官方文档]

## 8. 性能与 GPU
