## 1. 桌面端技术栈：不是 Electron，是 Qt6 + CEF + Node N-API 混合体

### 1.1 结论

剪映专业版 Windows 桌面端**不是 Electron 套壳**。实测全目录搜 `*.asar`、`electron*.exe`、`node.exe` 零命中，不存在 Electron 三件套。真实形态是：原生 C++ 核心（Qt6 做 UI 外壳）+ 内嵌 CEF（Chromium）跑 Web 面板 + 一批 Node.js N-API 原生插件，用 JavaScript 脚本驱动特效与 Agent 逻辑。

证据链 `[已验证-本地实测]`：

| 证据 | 实测值 |
|---|---|
| CEF 目录 | `cef\libcef.dll` 217 MB，FileVersion `121.0.0-m121.43+g85d7110+chromium-121.0.6167.86`，同目录 `chrome_100_percent.pak`、`resources.pak`、`snapshot_blob.bin`、`v8_context_snapshot.bin`、`icudtl.dat` |
| CEF 封装 | `CefCreator.dll` 3.2 MB、`PlatinumWebView.dll` 1.3 MB |
| Qt | `Qt6Core.dll` FileVersion `6.2.2.629`，另有 `Qt6Widgets / Qt6Quick / Qt6Qml / Qt6WebEngine?（无）/ Qt6Network / Qt6Sql / Qt6Svg`，`plugins\platforms`、`plugins\imageformats`、`plugins\sqldrivers` 齐全 |
| Node 插件 | `videoeditor_addon.node` 4.14 MB、`agent_runtime_addon.node` 8.37 MB、`skia.win32-x64-msvc.node` 27.4 MB、`image.win32-x64-msvc.node` 24.4 MB、`onnxruntime_binding.node` 301 KB（`.node` 是 Node N-API 二进制的扩展名，说明宿主内嵌了 Node 运行时） |

| 签名 | `JianyingPro.exe` / `VECreator.dll` 的 CompanyName 均为 `ByteDance`，FileVersion `11.7.0.14652` |

### 1.2 进程分工

- **`JianyingPro.exe`（438 KB）**：启动器 / 引导壳。注册表里它被注册为文件关联的执行体，负责解析命令行开关（见第 6 节）、做版本校验、拉起真正的引擎。`[已验证-本地实测]`
- **`VECreator.dll` / `cccreator.dll` / `videoeditor.dll`**：剪辑引擎、时间线、渲染、导出。`videoeditor.dll` 里能抽出 28 万条 ASCII 串，含大量 `[DRAFT_IO_MANAGER]`、`TimelineEditOperator`、`PatchService::onInit draft_path=` 这类内部日志模板 `[已验证-本地实测]`
- **CEF 渲染进程**：登录页、素材市场、AI 功能面板、活动页这类 Web 内容。`Resources\` 下 `image_h5_smart_lyrics`、`image_h5_smart_text`、`image_h5_smart_voiceover_script_v3`、`image_h5_smart_edit_chat_bot`、`image_h5_sticker_publish` 等一堆 `image_h5_*` 目录就是这些面板的离线包 `[已验证-本地实测]`
- **`JianyingProTray.exe`**（5.49 MB）：托盘 / 后台常驻，字符串里含 `https://staging-openapi-boe.byted.org`（字节内网 BOE 环境地址，属于内部测试域残留）`[已验证-本地实测]`
- **旁路子进程**：`VECrashHandler.exe`、`VEDetector.exe`、`VEHelper.exe`、`ETLHelper.exe`、`taskcontainer.exe`、`ffmpeg.exe`、`ffprobe.exe`、`lyra-cli.exe`（15.6 MB）、`jianying-agent-cli.exe`、`growvoice_crf_cutter.exe`、`parfait_crash_handler.exe` `[已验证-本地实测]`

### 1.3 值得注意：11.7 已经内置 Agent / LLM 链路

以下 dll 名称与体量直接说明 11.7 把「AI 剪辑 Agent」做进了本地进程：`DeepAgentsService.dll`（4.2 MB）、`deepagents_capi.dll`（39.2 MB）、`AICreator.dll`（618 KB）、`lyra_cli_client.dll`（13.1 MB）、`clipflow_sdk.dll`、`agent_runtime_addon.node`，配套 `Resources\agent_runtime\`、`Resources\agent_runtime_env\`、`Resources\canvas_agent\`、`Resources\article_video\`、`Resources\digital_human\` 资源目录，以及草稿目录里的 `key_value.json` 存 `kLocalAgentSessionInfoKey` → `conversation_id_list`。`[已验证-本地实测]`

`texts[0]` 实测：`content` 是一个**被转义的 JSON 字符串**，内含 `styles[].fill/content.solid.color`(0~1 浮点 RGBA)、`range`、`size`、`bold`、`strokes[].width`、`text`：
```json

```
`size:7` 是字号（剪映界面里的字号档位），`line_max_width:0.82` 对应自动换行行宽比例（pyJianYingDraft 的 `auto_wrapping` / `max_line_width` 直接映射这两个字段）。

`speeds[0]`：`{"curve_speed":null,"id":"...","mode":0,"speed":1.0,"type":"speed"}`。变速是**独立素材**，靠 segment 的 `extra_material_refs` 引用，不在 segment 上是 `speed` 值同时存在（两处都在：segment 的 `speed` 是只读汇总值）。

### 4.4 tracks 与 segments

实测 3 条轨道：`video/主视频`（85 段）、`text/字幕`（172 段）、`text/水印`（1 段）。

单条 track 结构：`{type, name, attribute, flag, id, segments: [...]}`。`type` 取 `video|audio|text|effect|filter|sticker`（后 4 种在 pyJianYingDraft 的 `TrackType` 枚举里，实测草稿里只出现前 3 种）。

**video segment 完整字段**实测：
```json
{
  "enable_adjust": true, "enable_color_correct_adjust": false,
  "enable_color_curves": true, "enable_color_match_adjust": false,
  "enable_color_wheels": true, "enable_lut": true, "enable_smart_color_adjust": false,

字段语义（实测 + 开源库交叉）：

### 4.5 keyframes

顶层 `keyframes` 是**按类型分组的桶**，实测 8 个空桶：`adjusts / audios / effects / filters / handwrites / stickers / texts / videos`；`keyframe_graph_list` 为空数组。
关键帧本体不挂在顶层 `keyframes`，而是挂在 segment 的 `common_keyframes[]` 上，形式为「属性名 + 相对片段头部的时刻 + 值」；pyJianYingDraft 的 `add_keyframe(KeyframeProperty.alpha, 时刻, 值)` 就是往这里写，且文档明确「关键帧优先级高于整体调节」。`[已验证-本地实测]` `[开源代码]` https://github.com/GuanYixuan/pyJianYingDraft

`config` 实测 23 键，是编辑器行为开关与任务态：

## 5. 加密体系：6.0 起草稿正文上锁

### 5.1 实测形态

11.7 保存的 `draft_content.json` 是**单行、无换行、首字节不是 `{`**，字符集为 `A-Z a-z 0-9 + /`（Base64 字母表）。三个草稿首 48 字节实测 `[已验证-本地实测]`：

| 文件 | 首 24 字符 |
|---|---|
| `小羊崽_长剪\draft_content.json` | `H908NZje4B9bz5zlEkR1GcabUrqn73Uj33Bc4c2FCd64G/1f` |
| `11.171电竞打手封10年_长剪\draft_content.json` | `6855YmmDBEhb4nmiezIxAC9Bc1wBrhRo/ae3iXojbfh9VRH5` |
| `11.171电竞打手封10年_长剪\draft_meta_info.json` | `d86IAbli6fEf8bbf5E76J97DhOQF7vXzk32g6OWQ40BDDjlE` |

`draft_meta_info.json` 同样上锁（3388 B / 3452 B 单行密文）。`draft.extra` 是带 `i/e` 标签的二进制壳，密文段在壳内。

### 5.2 引擎侧实现痕迹

从 `videoeditor.dll` 抽出的符号与日志模板 `[已验证-本地实测]`：

```

读出三件事：算法族是 **AES（Rijndael）+ AES-GCM 认证模式**，算法库是 **Crypto++**；密钥走 **key store（URI 映射的 keyring）**；密文格式带版本，存在 `updateCipherFormat` 升级路径，即格式随版本换代。`[推断]`（依据上是纯字符串证据，无运行时验证）

### 5.3 版本与协议号

第三方研究给出的版本矩阵 `[第三方研究]` https://gist.github.com/renezander030/521e6c6e8590a2a6e917009d9313bc55
：
- 5.9.x 及以下：`draft_content.json` 是明文 JSON，全部工具链可用
- 6.0.0～6.5.x：读取被阻断，`pyJianYingDraft` / `JianYingProDraft` / `capcut-cli` 写入全失效
- 7.0～9.x：同一套加密，封面图校验更严
- 10.0～10.3.x：加密 + macOS 上新建草稿报「内容已损坏」（`pyJianYingDraft` #177）
- CapCut 国际版 6.x～9.x 本地样本：实测未加密（该来源自己注明覆盖不全）

协议号对照 `[第三方研究]`（看雪帖）：剪映 5.9 对应 draft protocol **110**，剪映 11.3 对应 **183**；帖中称「草稿密钥放在 draft_content.json 文件内容里，从 v6.01 到 v11.3 都这样」。
来源：https://bbs.kanxue.com/thread-285223-1.htm

同一帖还记录了两个有用的旁证：8.9 版本「发布视频时会在 C 盘根目录临时生成解码后的 draft_content.json」；抓包发现启动会拉远端配置，其中含 `"draft_entryption_config": {"enable_all": true}`（原文拼写即 `entryption`）——**加密开关由云端配置下发**。`[第三方研究]`

本机实测的明文草稿 `version=360000` / `new_version=110.0.0`，正是外部工具按 5.9 协议（110）写出的，剪映 11.7 仍能打开；这印证「协议降级到 110 即可在旧版读写」的社区做法。`[已验证-本地实测]`+`[推断]`

### 5.4 生态现状（重要工程判断）

`pyJianYingDraft` 与 `capcut-cli` 两家都明确做了取舍：**只做检测，不做解密**。`capcut decrypt` 只返回结构化判决（`encrypted: true/false` + `reason` + `fix`），算法故意不进仓库，理由是「每个公开的解密脚本都在下一个剪映版本失效」。
来源：https://gist.github.com/renezander030/521e6c6e8590a2a6e917009d9313bc55 `[第三方研究]`

`pyJianYingDraft` README 里的对应表述：新版剪映的 `draft_content.json` 往往不是可直接读取的明文 JSON，加载模板要通过 `DraftFolder(..., fallback_loader=...)` 接外部读取器。
来源：https://github.com/GuanYixuan/pyJianYingDraft `[开源代码]`

### 9.3 草稿里怎么被引用

三层 ID：
- `resource_id`：素材资源 ID（大整数，如 `6758325170760323597`），指向服务端素材包
- `effect_id`：效果 ID（如 `871339`），指向效果算法
- `name` / `nameId`：展示名与内部名（如 `color_filter`）
- 另有 `md5`：素材包校验值（pyJianYingDraft 的 `EffectMeta.md5`）

草稿侧只写 `materials.effects[] / filters[] / transitions[] / material_animations[] / stickers[] / text_templates[]` 里的一条记录（含 `resource_id`、`effect_id`、`name`、参数数组），再由 segment 的 `extra_material_refs` 挂上。参数数组顺序按枚举表定义，导出成 `{name, value, default_value, min_value, max_value, parameterIndex, portIndex}`。
来源：`pyJianYingDraft/metadata/effect_meta.py` `[开源代码]` + 实测 `extra_material_refs` 结构 `[已验证-本地实测]`

`Lynx` 一系（`Resources\lynx_config\image_lynx_videocutpc_*` + `lynx_core.js`）是活动页/商业化面板的模板包，同样「配置 + JS」形态。

### 10.2 从网络特征看

所有云端能力共用一个域名族 `lv-api.ulikecam.com`（剪映后端），带统一的 `/lv/v1/common_task/{new,query,sync,cancel}` 异步任务框架 —— 即「提交任务 → 轮询/同步 → 拿结果下载」。草稿里对应的 `subtitle_taskinfo`、`lyrics_taskinfo`、`subtitle_recognition_id` 就是这套框架的落盘态。业务侧的 `sscronet.dll`（Cronet）+ `TTNet` 目录 + `TTNetDownloaderCrossPlatform.dll` 说明下载走字节自有网络栈，抓包看的是 Cronet 流量。`[已验证-本地实测]`

本地 AI 的判据是**模型文件 + 推理运行时 + NPU/GPU provider 三件套同时在场**：`Resources\models\` 60+ 目录里是 `.model` / `.bytenn` 权重，`onnxruntime.dll` / `bytenn_*` 是运行时，`openvino_intel_npu_plugin` / `QnnHtp` / CUDA provider 是加速后端。这三者齐备，说明美颜、抠像、插帧、追踪这些在断网下也跑得动。`[推断]`

## 11. 核心结论（给工程实现的落点）

1. 剪映桌面端是 **C++/Qt6 + CEF(Chromium 121) + Node N-API 混合体**，不是 Electron；`JianyingPro.exe` 只是 438 KB 启动器，引擎在 `VECreator.dll`（288 MB）`[已验证-本地实测]`
2. 草稿根目录 `%LOCALAPPDATA%\JianyingPro\User Data\Projects\com.lveditor.draft\<草稿名>\`，CapCut 国际版同结构 `[已验证-本地实测]` `[开源代码]`
3. `draft_content.json` 是唯一权威工程体（`draft_info.json` 只是同字节副本），时间单位**微秒**，`version=360000`，`new_version` 区分协议代次 `[已验证-本地实测]`
4. 剪映 **6.0 起 `draft_content.json` 与 `draft_meta_info.json` 上锁**，AES/Crypto++ + key store + 云端下发的 `draft_entryption_config.enable_all`；11.7 实测确为单行密文 `[已验证-本地实测]` `[第三方研究]`
5. **明文落盘仍是可行路径**：外部工具写的草稿剪映能读，剪映一另存才变密文。工程上应走「生成即交付、不做二次回存」`[已验证-本地实测]` `[第三方研究]`
6. 存在官方命令行入口：`-open-draft-pack="<.jypack>"` 与 `-open-file="<素材>"`，注册表 `JianyingPro.JYPack` / `JianyingPro.Media` 可查 `[已验证-本地实测]`
7. 剪映官方「开放平台」`open.capcut.cn` 是**插件形态**，不是时间线 API；REST 化的草稿操作能力由第三方 `capcut-mate` 提供 `[官方文档]` `[开源代码]`
8. 特效/转场/文字动画 = **参数化模板包**：`config.json` + `content.json` + `anim.prefab`/`xshader`/`js`，索引键是 `resource_id` / `effect_id` / `name` / `md5` `[已验证-本地实测]`
9. AI 能力双轨：**像素级与音视频算法在本地**（美颜、抠像、插帧、追踪、降噪，带 CUDA/OpenVINO/QNN 后端），**语义级在云端**（ASR 字幕、TTS 配音、翻译、Agent 成片）`[已验证-本地实测]` `[推断]`
10. `pyJianYingDraft`（Apache-2.0，0.3.1）是目前字段覆盖最全的开源实现，能力上限卡在「剪映 6 及以下能自动导出、7+ 只能生成草稿」；`pyCapCut`（0.0.4，无 LICENSE 文件）覆盖 CapCut 到 9.5.0.4050，不做导出 `[开源代码]`
