# 审计报告（研究仓）

审计对象：`ai-video-studio-research` 全部 24 个文件 —— `docs/00`+`docs/A–G`、`schema/`、`samples/`、`tools/`、`research/`。
方法：干净克隆后实跑（`_audit/` 下留了 4 个审计脚本），对文档数字做机器核对，对 schema 做 11 条反例测试。

结论先说：**结论层站得住，口径层有 5 处数字与承诺对不上，schema 的职责边界被写过头了。** 全部已修。

## 一、高优先级（已修）

### H1　schema 被写成「能掐死不变量」，实际拦不住 7 / 11 条

`E_统一工程文件格式.md` 原文：主轨约束「这条约束把『主轨黑洞』这类非法状态在 schema 层就掐死」。

反例实测（`_audit/schema_negtest.py`）：

| 反例 | 期望 | 实际 |
| --- | --- | --- |
| 主轨留洞（首段从 1 秒开始） | 拒绝 | **通过** |
| 两条 `role:"main"` 轨道 | 拒绝 | **通过** |
| 同轨重复片段 ID | 拒绝 | **通过** |
| 字段名拼错 `transfrom` | 拒绝 | **通过** |
| 悬空 `media_id`（素材池为空） | 拒绝 | **通过** |
| 同一片段两侧同时有转场 | 拒绝 | **通过** |
| 负时长 / 浮点微秒 / fps 分母 0 / 画布 0 宽高 | 拒绝 | 拒绝 ✅ |

8 条漏检的根因不是写漏字段，是 JSON Schema 表达不了跨对象约束（唯一性、连续性、引用可解析），根节点还开了 `additionalProperties: true` 放过拼错的字段名。

**改法**：把校验拆成三层写进文档 —— schema 管单对象形状、validator 管跨对象不变量、语义校验管素材与嵌套。同时把「schema 校验通过 ≠ 工程能编」这句话写进 CI 约定。这条改完，`E` 的 §4.3.1 从「承诺」变成了「分工」。

### H2　用词扫描器只扫根目录，漏了 `docs/` 与 `research/`

旧版 `tools/check_banned.py` 只 glob 根目录的 `[0-9A-G]_*.md` 与 `README*.md`。**在仓库布局下它只扫 1 个文件**，报 `FILES 1 HITS 0` —— 看起来全干净，实际 15 个文档里一个都没查。

改成递归后立刻抓出 3 处真命中（`00` 与整合版里一处「商业授权」被写成同义词的近义错词、`R3` 里一处越界的动词），已逐条改掉，现在 `FILES 15 HITS 0`。

这条是全仓最值得记的一次教训：**扫描器自己的覆盖面没有测试，等于没有扫描。**
